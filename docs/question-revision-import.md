# Question revision import

The checked-in research document `docs/research/question-revisions-20261010.json` is the source for this bounded nine-question update. The importer validates its pinned SHA-256, schema, baseline commit, reviewed qid set, provenance and `NOT_RUN` status before planning changes.

Run `npm run question:revisions` for the default dry-run. It validates the source and current baseline, then reports the planned canonical and generated files without writing. Apply only with `npm run question:revisions -- --apply`. The apply updates the nine named master questions and their chapter titles, then regenerates the repository's existing question, topic and content-manifest indexes. It can also repair the known prior A15 extraction result only when the full question, provenance, title and chapter reference match the approved source exactly and the checkpoint array matches that prior extraction byte for byte. Unknown or duplicate qids, unexpected fields, blank content, changed source hash, mismatched question baselines or a partially applied batch fail closed. A repeated apply reports `already-applied` and does not replace later edits.

Apply takes an exclusive `.question-revisions.lock` in the checkout before reading any content. The lock covers source validation, baseline preparation, candidate generation and install. It rejects another importer instead of waiting. The importer records hashes of all five canonical/generated files it reads and checks them again immediately before install and before each replacement, so an intervening edit is preserved and the batch aborts. Other tools should honor the same checkout lock; the hash checks also detect ordinary edits that do not.

The importer generates all candidate files in a temporary stage directory, records each candidate hash before installation, copies the original files into a backup area, and installs each candidate by rename. If an install operation fails, it restores files already moved only while each destination still matches this run's candidate hash. If another process edits an installed destination before rollback reaches it, that destination is preserved and the importer reports that manual recovery is required; the stage and every original recovery backup remain in place. This is a recoverable multi-file install, not a filesystem-wide atomic transaction. Inspect the retained backups and preserved destination before manual recovery. A hard process termination can leave both a stage directory and lock behind; verify no importer is running, inspect the lock metadata and staged backups, then remove a stale lock manually. The tool deliberately does not guess whether a lock is stale or delete it automatically.
